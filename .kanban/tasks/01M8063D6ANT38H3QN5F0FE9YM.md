title: 'Inkling 2 MTP: cheaper verify rows (shared projection weight reads)'
---
An Inkling 2 verify pass runs its rows through the decode kernels (^04yn8q4). For bit-exact rows the projections and lm_head run one MLX qmv per row through a non-contiguous `[L, 1, D]` view, so each row re-reads the weights: `MultiRowQuantizedMatvec` (which reads weights once and matches `qmv_fast`) does not run for K = 2304 (2304 % 512 != 0, MLX runs the generic `qmv` there). Measured on the M5 (short context): decode 13.5 ms, verify L=2 13.0 ms, L=4 17.9 ms, L=8 28.4 ms; the per-row cost (~2.5 ms) is mostly expert weight bandwidth, the rest projection/lm_head re-reads.

Extend the bit-exact multi-row matvec to the generic `qmv` layout (K not a multiple of 512) and use it for the Inkling verify rows; also consider an Inkling default block size of 3 (fastest measured: 1.13x prose, 1.44x code vs 1.02x/1.37x at the shared default 4).
