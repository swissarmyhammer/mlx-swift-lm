#prompt-cache

(Plan item F6, in the form the FoundationModelsRouter session asked for on 2026-09-24.)

## What

The executor names a session by the id of the first transcript entry (`Libraries/MLXFoundationModels/MLXLanguageModel.swift:695-700`). That is wrong for a host that knows its sessions: a fork copies its parent's transcript and gets the parent's key, and a compaction that drops the first entry changes the key. A summarizer call adds a new key each time and pushes real sessions out.

Add a public task-local that the host binds around its call to the executor:

```swift
extension MLXLanguageModel {
    public enum PromptCacheScope: Sendable, Hashable {
        /// The pass belongs to this session. The host owns the identifier.
        case session(String)
        /// The pass takes no carried cache and leaves none.
        case none
    }
    @TaskLocal public static var promptCacheScope: PromptCacheScope?
}
```

- `Executor.sessionCacheKey(for:modelID:)` reads `MLXLanguageModel.promptCacheScope` first: `.session(id)` gives `ExecutorPromptCacheKey(modelID:, sessionID: id)`; `.none` gives nil (the executor then checks out nothing and checks in nothing, as for an empty transcript today); unset (nil) keeps the current rule (first entry id).
- Path verified in the code: `respond` (`:874-887`) → `withTaskCancellationHandler` → `$drainCoordinator.withValue` → `runRespond` (`:902`) → `sessionCacheKey` (`:973`), all on one task, no detached task. The executor already uses the task-local `drainCoordinator` the same way.
- Doc comment text (do not claim more): "The binding is guaranteed to reach the executor only when the host calls `Executor.respond` directly, on the same task that binds it."
- `sessionCacheKey` is computed once and used for both check-out and check-in (`:1107`). Keep it that way.

## Acceptance Criteria
- [x] With `.session("A")` bound, two passes with different first entry ids share one cache (the second is warm).
