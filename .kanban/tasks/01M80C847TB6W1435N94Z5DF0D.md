Release `LFM2CheckpointIntegrationTests` (2026-11-21, run for ^04yn8q4) fails 2 of 6 tests:
- `denseCheckpointLoadsThroughFactory()`: `context.configuration.reasoningConfig?.promptStrategy == .alwaysOn` fails.
- `moeCheckpointLoadsWithMixedPrecisionRouting()`: the same check fails, and so does `reasoningConfig?.isSpecialToken == false`.

Likely cause, not yet confirmed: the tests load `LLMModelFactory.shared.load(from: directory, ...)` with the resolved hub snapshot directory. `LLMModelFactory` passes that configuration's `modelId` to `conventionsRegistry.reasoningConfig(modelId:modelType:)`, and `LFM25ConventionsResolver` (Libraries/MLXLMCommon/ChatConventionsRegistry.swift) matches only model names that start with `lfm2.5-2.6b`, `lfm2.5-8b-a1b` or `lfm2.5-1.2b-thinking`. A snapshot directory's last path component is a commit hash, so the resolver returns nil. The change for ^04yn8q4 touched only the `drain` helper of this file, and the tests that use drain pass.

Do this: confirm the failure at HEAD before ^04yn8q4. Then decide on the fix: the factory derives the model id from the hub id for a directory load, or the test loads by `ModelConfiguration` id. Run the suite on its own (Release, under the GPU lock).

## Resolution

Commits 658540cd, 7a1fe592 (branch inkling2-side).

- Confirmed at 99f1f242 (stable before Inkling MTP, scratch worktree): `denseCheckpointLoadsThroughFactory()` and `moeCheckpointLoadsWithMixedPrecisionRouting()` fail with the same 3 issues. Cause confirmed: the factory keyed the conventions resolver on `ModelConfiguration.name`, which for the hub snapshot `.../models--LiquidAI--LFM2.5-2.6B-MLX/snapshots/b41f2b65...` is `snapshots/b41f2b65...`.
- Fix in the factory (so real directory loads get the right conventions): `ModelConfiguration.repositoryID` — the repo ID of `.id`; for a directory in the hub-cache layout (`models--<org>--<name>/snapshots/<rev>[/...]`) the `<org>/<name>` it encodes; else `name`. `ResolvedModelConfiguration` carries it (`resolved(...)` passes it, `init(directory:)` derives it). `LLMModelFactory` and `VLMModelFactory` key the conventions registry and the VLM processor context on `repositoryID`. `name` (display, prompt-cache keys) unchanged.
- Unit tests: `HubSnapshotRepositoryIDTests` (id, snapshot, variant below a snapshot, non-cache paths, resolved forms, and a factory load of a tiny LFM2 checkpoint in a hub-snapshot-shaped directory that gets the LFM2.5 `.alwaysOn` reasoning).
- `LFM2CheckpointIntegrationTests` (Release, alone, under the lock): 6/6 pass after the fix.
- All 5 bundles green.
- Review: findings only on the unchanged `ResolvedModelConfiguration` properties -> follow-up ^jf539s.
