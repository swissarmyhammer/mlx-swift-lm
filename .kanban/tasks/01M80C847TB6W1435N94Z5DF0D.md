Release `LFM2CheckpointIntegrationTests` (2026-11-21, run for ^04yn8q4) fails 2 of 6 tests:
- `denseCheckpointLoadsThroughFactory()`: `context.configuration.reasoningConfig?.promptStrategy == .alwaysOn` fails.
- `moeCheckpointLoadsWithMixedPrecisionRouting()`: the same check fails, and so does `reasoningConfig?.isSpecialToken == false`.

Likely cause, not yet confirmed: the tests load `LLMModelFactory.shared.load(from: directory, ...)` with the resolved hub snapshot directory. `LLMModelFactory` passes that configuration's `modelId` to `conventionsRegistry.reasoningConfig(modelId:modelType:)`, and `LFM25ConventionsResolver` (Libraries/MLXLMCommon/ChatConventionsRegistry.swift) matches only model names that start with `lfm2.5-2.6b`, `lfm2.5-8b-a1b` or `lfm2.5-1.2b-thinking`. A snapshot directory's last path component is a commit hash, so the resolver returns nil. The change for ^04yn8q4 touched only the `drain` helper of this file, and the tests that use drain pass.

Do this: confirm the failure at HEAD before ^04yn8q4. Then decide on the fix: the factory derives the model id from the hub id for a directory load, or the test loads by `ModelConfiguration` id. Run the suite on its own (Release, under the GPU lock).
