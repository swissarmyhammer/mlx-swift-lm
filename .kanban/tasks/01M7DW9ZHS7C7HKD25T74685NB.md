title: 'GLM tool-call parser: recover arg_key/arg_value pairs nested inside an argument value'
---
Flint (flint2 bench, django-13447, stable 73523140) wrote a GLM tool call whose single argument value mixes JSON and GLM tags:

`<tool_call>skills<arg_key>arguments</arg_key><arg_value>{"op</arg_key><arg_value>use skill","id</arg_key><arg_value>kanban"}</arg_value></tool_call>`

`GLM4ToolCallParser` keeps the value as the literal string `{"op</arg_key><arg_value>use skill","id</arg_key><arg_value>kanban"}` under `arguments`, so every call fails ("Unknown operation").

Postel fix: when an argument value contains `</arg_key><arg_value>` pairs, recover the inner pairs and use them as the call's arguments, replacing the wrapper key. Each inner value gets the same schema-typed deserialization as a top-level value. Recover only when every inner key is identifier-like, so that literal markup in free text (file contents) stays unchanged.

- [ ] Failing test: the observed `arguments` wrapper → {op: "use skill", id: "kanban"}
- [ ] Failing test: single inner pair `{"op</arg_key><arg_value>list skill"}` → {op: "list skill"}
- [ ] Failing test: tag-nested pairs inside a value
- [ ] Control: well-formed calls unchanged; non-identifier inner text stays literal
