title: 'Guided MTP: hand over a finalized drafter continuation so the next turn''s drafter starts warm'
---
## What
Since ^nztjxdh a guided pass checks its ledger into the prompt cache, but `ExecutorGuidedHandOff.commit` checks in no MTP drafter continuation: `GuidedSpeculation` keeps an `MTPDrafterState` with an entry for the pending token and never finalizes it (the plain path does this in `MTPSpeculativeTokenIterator` via `finalizeDrafterState`). The next turn after a guided turn therefore cold-starts its drafter where the cache ends — output is unchanged, acceptance on the first rounds is lower.

## Fix
- At the end of a local guided speculative generation, finalize the drafter state at the main cache position (`ResumableMTPDrafterModel.finalizeDrafterState`) and hand it over through `GuidedCacheHandOff`; commit it with the entry (`commitOutcome` keeps it only when aligned with the ledger).
- A prompt-end checkpoint of a guided pass can keep the drafter continuation of the prefill feed too.

## Tests
- After a speculative guided turn, the entry's drafterState is aligned with the ledger, and the next speculative turn resumes it (no cold start) with output equal to a cold turn.
