title: Prompt-cache disk budget is zero when macOS reports 0 important-usage capacity

## Why
After the 2026-11-17 crash and restart, `volumeAvailableCapacityForImportantUsage` returns 0 for the boot volume while `volumeAvailableCapacity` returns ~240 GB (probed with a standalone Swift script). `ExecutorPromptCacheStore.availableCapacity(ofVolumeOf:)` (Libraries/MLXFoundationModels/ExecutorPromptCache.swift ~579) uses only the important-usage key, so `defaultDiskBudgetBytes` is 0 and every spilled file is evicted at once ("disk evict" right after "spill … on disk"). In production that silently disables the disk tier; in tests 44 spill/restore expectations fail in MLXFoundationModelsTests (also at 31e5cfc9, which passed before the crash).

## What
- When the important-usage capacity is 0 (or missing) but `volumeAvailableCapacityKey` is positive, fall back to that value (or a documented conservative fraction). Log which source was used.
- Make the tests that need a disk budget independent of the host volume: inject the capacity (the store already has `configure(diskBudgetBytes:)` / `defaultDiskBudgetBytes(availableCapacity:)`) so the suite is deterministic.
