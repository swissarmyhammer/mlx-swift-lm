#prompt-cache

(The offset part of F4 is now its own task, which depends on this one.)

## What

The disk spool must read a session's caches back, also in a new process. `loadPromptCacheSnapshot(url:)` (`Libraries/MLXLMCommon/KVCache.swift:2033`) rebuilds each cache from its saved class name through `restoreCacheFromMetaState` (`KVCache.swift:2191`). Two gaps:

1. `DeepSeekV4Cache` (`Libraries/MLXLLM/Models/DeepSeekV4Cache.swift:363`) is not registered in `KVCacheSerializationRegistry`. It is saved as `"KVCache"`, and the load throws. Its `init` needs a `DeepSeekV4Configuration`, thus a `(state, metaState)` factory cannot build it.
2. `MiniMaxM3KVCache` (`Libraries/MLXVLM/Models/MiniMaxM3.swift:1485`) registers lazily from its own `init()` (`:1522`). In a new process, a load before the first instance fails with "Unknown cache class".

The fix: restore the saved state INTO caches that the model made (`model.newCache(parameters:)`).

- In `KVCache.swift`, add `public func loadPromptCacheSnapshot(url: URL, into templates: [KVCache]) throws -> PromptCacheSnapshot`.
- For each layer `i`, match the saved class name against `cacheClassName(templates[i])`. Throw `KVCacheError` on a layer-count mismatch.
- Converted layers: generation can change a `KVCacheSimple` layer into `QuantizedKVCache` (`maybeQuantizeKVCache`) or `TurboQuantKVCache`, and `newCache(parameters:)` never gives those classes. For a `KVCacheSimple` template, accept a saved `QuantizedKVCache` or `TurboQuantKVCache` and build that layer with the existing restore path (`restoreCacheFromMetaState`). Any other mismatch throws.
- VALIDATE BEFORE ANY SETTER RUNS. The setters stop the process on bad input: `KVCacheSimple.state` has `fatalError` for a count other than 2, `MiniMaxM3KVCache.state` has `fatalError` in its `default:` case, `ArraysCache.metaState` has `assertionFailure`. For each class, check the state-array count, the array rank, and the metaState count first, as `validatePromptCache` does for the existing path (`KVCache.swift:2385`). Include `DeepSeekV4Cache` with and without an indexer (window state 0 or 2 arrays + the branch slots) and `MiniMaxM3KVCache` with 2 or 3 arrays.
- Then restore: `ArraysCache`/`MambaCache` through `restoreFromMetaState(state:savedMetaState:)`; `CacheList` into the template's own children; other types through `state` and `metaState`.
- The safetensors load is lazy (`Libraries/MLXLMCommon/Load.swift:9-15`): evaluate the restored arrays before the function returns, thus the caller can delete the file. Say so in the doc comment.
- A throw leaves the templates in an undefined state: say in the doc comment that the caller discards them.
- Keep `loadPromptCacheSnapshot(url:)` unchanged.
