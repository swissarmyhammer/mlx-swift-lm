title: 'Inkling 2 MTP: bit-exact verify past the sliding window'
---
Below the 1024-token sliding window an Inkling 2 verify pass computes every token's logits bit for bit as decode steps do (^04yn8q4). Past it, plain decoding reads each sliding layer's keys from a wrapped `RotatingKVCache` ring (ring order), while a verify pass writes several rows through the concat path and reads them in temporal order, so the attention sums run in another order and bfloat16 near ties can round apart (`Inkling2MTPIntegrationTests.throughputAtShortAndLongContext` accepts a divergence past the window only as a near tie, gap <= 0.5 logit).

Make the verify read each row's keys in the slot order plain decoding would have at that row's position (or make plain decoding and the verify share one layout), keeping the decode kernels' speed, and tighten the long-context check to exact equality.
