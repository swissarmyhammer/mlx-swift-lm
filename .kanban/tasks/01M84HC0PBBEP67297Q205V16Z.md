## Why
^jddp2ck compiled the one-row decode only. Plain decode went from 80.7 to 101.8 tok/s, but MTP speed did not move. The verify pass is still the eager, host-bound path.

Inkling2MTPIntegrationTests (Release, M5 Ultra):

| | stable | with ^jddp2ck |
|---|---|---|
| decode L=1 | 13.55 ms | 10.48 ms |
| verify L=2 | 12.77 ms | 12.51 ms |
| verify L=4 | 17.33 ms | 17.43 ms |
| verify L=8 | 26.60 ms | 27.27 ms |
| short, plain / MTP block 3 | 80.7 / 95.5 (1.18x) | 101.8 / 95.8 (**0.94x**) |
| long, plain / MTP block 3 | 76.7 / 116.0 (1.51x) | 94.3 / 116.1 (1.23x) |
| chat turns, MTP | ~121 tok/s | ~121 tok/s |

At short contexts MTP is now slower than plain decoding.

## What
- Trace the sequential path of `Inkling2DecoderLayer.decode`, for rows 2...16, in segments around the attention cache, as `compiledDecode` does.
- Inside the trace: the rowwise projections, the prologue, the chained convolution states, the depth mixes, the controllers, the routed experts and the expert convolution.
- Outside the trace: `cache.update` with the causal-rows attention, and storing the windows into `SpeculativeConvolutionCache`. Those are cache side effects.
- The row count is part of each trace's shape, so each layer gets up to 15 shapes.
- Then retune the per-drafter preferred MTP block against the new plain speed.
